# Stelody 프론트엔드

React SPA의 공통 UI와 공개 노래 탐색 화면입니다. 홈에서 최신곡·무작위 추천·멤버를 조회하고 전체곡 목록과 검색 화면으로 이동할 수 있습니다.

## 로컬 실행

Node.js 24 LTS와 npm 10 이상을 사용합니다. `frontend/`에서 실행합니다.

```sh
nvm use
npm ci
npm run dev
```

화면은 `http://localhost:5173`입니다. `/api` 요청은 기본적으로 `http://localhost:8080`으로 전달합니다. 백엔드는 [백엔드 실행 안내](../backend/README.md)를 따릅니다. 프록시 목적지를 바꾸려면 `.env.example`을 `.env.local`로 복사하고 `API_PROXY_TARGET`을 설정합니다.

`VITE_API_BASE_URL`은 브라우저 요청 주소이며 기본값은 `/api/v1`입니다. 배포 구조가 정해지면 이 값과 호스팅 프록시·CORS·쿠키·OAuth 콜백을 함께 검증합니다. Vite 환경변수는 사용자에게 공개되므로 비밀키를 넣지 않습니다. Google 로그인은 실제 브라우저 이동으로 연결하며 세션 쿠키를 JavaScript로 읽지 않습니다.

## 구조

- `src/app`: 앱 시작, 라우터, Query 설정, 전역 스타일
- `src/pages`: 경로별 화면
- `src/features`: 곡 API·Query 옵션·곡 카드와 멤버 조회 등 기능별 모듈
- `src/shared`: API, 공통 유틸리티와 후속 UI 컴포넌트
- `src/test`: Vitest·React Testing Library·MSW 기반
- `e2e`: Playwright 브라우저 검증

Tailwind Vite 플러그인과 shadcn/ui의 `components.json`·경로 별칭을 준비했습니다. 공통 `Button`은 Radix Slot과 cva를 사용하며 링크에도 같은 스타일을 적용합니다. 폼·차트·드래그 패키지는 해당 기능을 시작할 때 추가합니다.

## 홈과 공개 곡 목록

- `/`: 최신 공개곡 4개, 무작위 추천 4개와 다시 추천, 졸업 멤버를 포함한 멤버 탐색을 제공합니다. 급상승은 준비 중 상태입니다.
- `/songs`: 공개일 최신순의 전체 곡을 20개씩 조회합니다. 커서를 그대로 전달하고 페이지 사이 중복 ID를 제거합니다. 화면 하단에서 자동으로 추가 조회하며 더 보기 버튼으로도 조회할 수 있습니다.
- 추가 페이지 실패 시 기존 카드를 유지하며 같은 커서로 재시도합니다. 뒤로 가기에서는 캐시된 목록과 스크롤 위치를 복원합니다.
- 썸네일·프로필은 API URL을 사용합니다. 이미지 미등록·로드 실패와 원곡 정보 미등록에 대한 기본 표시를 제공합니다. 공개일은 한국 시간 기준입니다.
- 홈 검색 폼은 `/search?q=...`로 연결합니다. 모든 멤버는 멤버 목록으로 연결합니다. 멤버 상세는 준비 중 화면입니다.
- 서버 데이터는 TanStack Query로 관리하며 화면을 벗어날 때 요청 취소 신호를 전달합니다.

## 검색 화면

- `/search`: 검색어·곡 유형·멤버 다중 선택·정렬을 URL로 관리합니다. 새로고침과 뒤로 가기에서 조건을 복원합니다.
- 입력·유형·멤버 조건은 검색 결과 보기 또는 Enter로 적용하고 정렬은 즉시 적용합니다. 새 조건의 첫 페이지부터 조회하며 이전 요청의 취소 신호를 전달합니다.
- 검색어 또는 곡 유형·멤버·기간 필터가 있으면 검색할 수 있습니다. 검색어와 필터가 모두 없으면 요청하지 않으며, 정렬만 바꿔도 검색하지 않습니다. 검색어가 있으면 SEARCH·관련도순, 필터만 있으면 검색어를 생략한 BROWSE·최신순으로 조회합니다.
- 검색어는 서버에 전달하며 공백·영어 대소문자 무시와 한국어 별칭 검색은 서버 검색 규칙을 사용합니다. 프론트에서 번역하거나 별칭을 고정하지 않습니다.
- 결과 수·로딩·빈 결과·오류·재시도·커서 추가 로딩을 제공합니다. 갱신이나 추가 조회가 실패해도 받은 결과를 유지합니다.
- 시작일·종료일을 URL과 API에 연결합니다. 한국 시간 공개일 기준으로 양 끝 날짜를 포함하며 한쪽만 지정할 수 있습니다. 날짜 형식·1900~2100 범위·기간 역전을 검증하고 기간 변경 시 첫 페이지부터 조회합니다. 서버 날짜 오류는 필드별로 안내합니다.

## 노래 상세

- `/songs/:songId`: 곡 상세와 대표 영상의 조회수를 각각 조회합니다. 잘못된 UUID는 요청하지 않고, 비공개·없는 곡은 접근 불가 상태로 안내합니다.
- 참여 멤버는 프로필 경로에 연결하고 외부 아티스트는 이름으로 표시합니다. 곡과 원곡의 링크·노래방 번호는 별도로 표시하며 미확인·미수록·등록 상태를 구분합니다.
- 재생 버튼을 누른 뒤에만 YouTube 임베드를 로드합니다. 임베드가 불가능한 영상도 원본 링크를 제공합니다. 권장 검색어의 복사 성공·실패를 안내합니다.
- 7일·30일 조회수는 대표 영상과 기간별 캐시로 관리합니다. 누적 선 그래프·일별 증가량 막대그래프를 전환해도 기간을 유지하며, 총 조회수와 수집 시작·최종 관측·집계 갱신 시각을 표시합니다. 마우스 사용 시 그래프 호버 위치의 툴팁으로 값과 관측 시각을 확인하며, 터치와 표의 날짜 버튼은 선택 정보 영역에 표시합니다. 대표 영상 불일치 시 통계 대신 곡 정보 재조회를 안내합니다.
- 일별 증가량은 연속된 한국 날짜의 관측값 차이입니다. 미수집은 `미수집`, 전날 값이 없으면 `계산 불가`, 실제 0은 `0회`로 구분하며 결측을 건너뛰어 계산하거나 음수 차이를 0으로 바꾸지 않습니다. 현재 API는 조회 범위 직전 날짜를 제공하지 않으므로 범위 첫날은 계산 불가입니다. 오늘은 부분 집계 표시와 옅은 점선 막대를 사용합니다.
- 막대축은 0을 포함하고 실제 데이터 범위로 상한을 정합니다. 곡·기간 간 공통 축 범위는 아직 확정하지 않았으며 Figma 예시 수치를 고정하지 않습니다.
- 같은 원곡의 다른 커버는 서버의 `relatedSongs`를 순서대로 표시합니다. 같은 원곡·다른 확정 멤버 조건과 정렬은 서버에서 적용하며 최대 6개이고 추가 페이지는 없습니다. 반환된 커버가 없으면 섹션 전체를 숨깁니다.
- 상세 조회 실패와 통계 조회 실패는 독립적으로 처리합니다. 즐겨찾기·플레이리스트 저장 버튼은 준비 중 상태입니다.

## 멤버 목록

- `/members`: 홈과 목록 캐시를 공유하며 졸업 멤버를 포함한 서버 순서를 유지합니다. 커서 추가 조회, 중복 제거, 로딩·빈 목록·실패 재시도를 제공합니다.

## API 계약

`openapi/stelody.json`은 같은 원곡의 다른 커버 보완 기준 커밋 `d494df67c1fbf03f2a426cafad8930fc6b457d65`의 전달된 검증 명세를 반영한 스냅샷입니다. [기준 CI 실행](https://github.com/MinHyukJi1226/Stelody/actions/runs/38911979438)이 제공되었으며, 2026-10-16 운영 명세와 JSON 내용의 일치를 확인했습니다. 저장 시 프로젝트 JSON 포맷을 적용하므로 파일 바이트 일치를 의미하지 않습니다.

명세는 수동으로 편집하지 않습니다. 백엔드 변경 시 해당 커밋의 검증된 CI 아티팩트에서 교체하고 아래 명령으로 타입을 생성합니다.

```sh
npm run api:generate
npm run api:check
```

생성 타입은 `src/shared/api/generated/schema.d.ts`에 보관합니다. `api:check`는 외부 서버를 호출하지 않고 저장된 명세에서 다시 생성한 결과를 비교합니다. 새 타입이 현재 운영 서버와 일치하는지는 연동 시 별도 확인합니다.

공통 클라이언트는 `/`로 시작하는 API 상대 경로를 받습니다. 공개 GET은 CSRF를 조회하지 않고, 변경 요청은 메모리에 보관한 CSRF 토큰을 사용합니다. 동시 변경의 토큰 조회는 공유합니다. `401`·`403` 및 로그아웃 후 토큰을 비웁니다. 로그인·재인증 완료 후 기능 모듈에서 `apiClient.invalidateCsrf()`를 호출해야 합니다. 다음 변경 요청에서 새 토큰을 조회합니다.

변경 요청은 자동 재시도하지 않습니다. `ApiError`의 `status`, `code`, `fieldErrors`, `traceId`로 분기하고, 알 수 없는 오류는 일반 안내로 처리합니다. 검색 요청 취소에는 `signal`을 전달합니다. 요청의 제네릭 타입은 TypeScript 계약이며 응답 전체의 런타임 검증을 의미하지 않습니다.

인증 UI와 로그아웃의 개인 Query 캐시 제거는 후속 인증 작업 범위입니다. 개인 데이터를 localStorage에 저장하지 않습니다.

## 검증

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

`check`는 API 생성 타입, lint, 포맷, 단위·모듈 테스트, 타입 및 프로덕션 빌드를 검사합니다. E2E는 빌드된 앱을 4173 포트로 실행합니다. 고정된 API 응답으로 홈 조회·추천 갱신·빈 결과·실패 재시도·커서 추가 로딩·중복 제거·뒤로 가기 위치 복원과 데스크톱·모바일 공통 조작을 확인합니다. 운영 데이터나 계정에 의존하지 않습니다.

CI는 기존 Backend CI에서 재사용 Frontend CI를 호출합니다. 최종 `required-checks`와 main 이미지 게시가 프론트 검증 성공도 요구합니다. 배포 방식과 프론트 배포 산출물 연결은 아직 변경하지 않았습니다.

실제 Google·YouTube·관리자 계정 연동은 후속 기능에서 검증합니다.
