# Stelody 프론트엔드

React SPA의 공통 UI와 공개 노래 탐색 화면입니다. 홈에서 최신곡·무작위 추천·멤버를 조회하고 전체곡 목록과 검색 화면으로 이동할 수 있습니다.

## 로컬 실행

Node.js 24 LTS와 npm 10 이상을 사용합니다. `frontend/`에서 실행합니다.

```sh
nvm use
npm ci
npm run dev
```

화면은 `http://localhost:5173`입니다. `.env.example`을 `.env.local`로 복사하면 `/api` 요청을 운영 백엔드로 전달합니다. 로컬 백엔드를 사용할 때는 `API_PROXY_TARGET=http://localhost:8080`으로 변경합니다. 백엔드 실행은 [백엔드 실행 안내](../backend/README.md)를 따릅니다. 환경변수 변경 후 Vite를 재시작합니다.

`VITE_API_BASE_URL`은 브라우저 요청 주소이며 기본값은 `/api/v1`입니다. 배포 구조가 정해지면 이 값과 호스팅 프록시·CORS·쿠키·OAuth 콜백을 함께 검증합니다. Vite 환경변수는 사용자에게 공개되므로 비밀키를 넣지 않습니다. Google 로그인은 실제 브라우저 이동으로 연결하며 세션 쿠키를 JavaScript로 읽지 않습니다.

## 구조

- `src/app`: 앱 시작, 라우터, Query 설정, 전역 스타일
- `src/pages`: 경로별 화면
- `src/features`: 곡 API·Query 옵션·곡 카드와 멤버 조회 등 기능별 모듈
- `src/shared`: API, 공통 유틸리티와 후속 UI 컴포넌트
- `src/test`: Vitest·React Testing Library·MSW 기반
- `e2e`: Playwright 브라우저 검증

Tailwind Vite 플러그인과 shadcn/ui의 `components.json`·경로 별칭을 준비했습니다. 공통 `Button`은 Radix Slot과 cva를 사용하며 링크에도 같은 스타일을 적용합니다. 폼·차트·드래그 패키지는 해당 기능을 시작할 때 추가합니다.

## 홈과 공개 곡 목록

- `/`: 최신 공개곡 4개, 무작위 추천 4개와 다시 추천, 졸업 멤버를 포함한 멤버 탐색을 제공합니다. 급상승은 준비 중 상태입니다.
- `/songs`: 공개일 최신순의 전체 곡을 20개씩 조회합니다. 커서를 그대로 전달하고 페이지 사이 중복 ID를 제거합니다. 화면 하단에서 자동으로 추가 조회하며 더 보기 버튼으로도 조회할 수 있습니다.
- 추가 페이지 실패 시 기존 카드를 유지하며 같은 커서로 재시도합니다. 뒤로 가기에서는 캐시된 목록과 스크롤 위치를 복원합니다.
- 썸네일·프로필은 API URL을 사용합니다. 이미지 미등록·로드 실패와 원곡 정보 미등록에 대한 기본 표시를 제공합니다. 공개일은 한국 시간 기준입니다.
- 홈 검색 폼은 `/search?q=...`로 연결합니다. 모든 멤버와 개별 프로필은 멤버 목록·상세 화면으로 연결합니다.
- 서버 데이터는 TanStack Query로 관리하며 화면을 벗어날 때 요청 취소 신호를 전달합니다.

## 검색 화면

- `/search`: 검색어·곡 유형·멤버 다중 선택·정렬을 URL로 관리합니다. 새로고침과 뒤로 가기에서 조건을 복원합니다.
- 입력·유형·멤버 조건은 검색 결과 보기 또는 Enter로 적용하고 정렬은 즉시 적용합니다. 새 조건의 첫 페이지부터 조회하며 이전 요청의 취소 신호를 전달합니다.
- 검색어 또는 곡 유형·멤버·기간 필터가 있으면 검색할 수 있습니다. 검색어와 필터가 모두 없으면 요청하지 않으며, 정렬만 바꿔도 검색하지 않습니다. 검색어가 있으면 SEARCH·관련도순, 필터만 있으면 검색어를 생략한 BROWSE·최신순으로 조회합니다.
- 검색어는 서버에 전달하며 공백·영어 대소문자 무시와 한국어 별칭 검색은 서버 검색 규칙을 사용합니다. 프론트에서 번역하거나 별칭을 고정하지 않습니다.
- 결과 수·로딩·빈 결과·오류·재시도·커서 추가 로딩을 제공합니다. 갱신이나 추가 조회가 실패해도 받은 결과를 유지합니다.
- 시작일·종료일을 URL과 API에 연결합니다. 한국 시간 공개일 기준으로 양 끝 날짜를 포함하며 한쪽만 지정할 수 있습니다. 날짜 형식·1900~2100 범위·기간 역전을 검증하고 기간 변경 시 첫 페이지부터 조회합니다. 서버 날짜 오류는 필드별로 안내합니다.

## 노래 상세

- `/songs/:songId`: 곡 상세와 대표 영상의 조회수를 각각 조회합니다. 잘못된 UUID는 요청하지 않고, 비공개·없는 곡은 접근 불가 상태로 안내합니다.
- 참여 멤버는 프로필 경로에 연결하고 외부 아티스트는 이름으로 표시합니다. 곡과 원곡의 링크·노래방 번호는 별도로 표시하며 미확인·미수록·등록 상태를 구분합니다.
- 재생 버튼을 누른 뒤에만 YouTube 임베드를 로드합니다. 임베드가 불가능한 영상도 원본 링크를 제공합니다. 권장 검색어의 복사 성공·실패를 안내합니다.
- 7일·30일 조회수는 대표 영상과 기간별 캐시로 관리합니다. 누적 선 그래프·일별 증가량 막대그래프를 전환해도 기간을 유지하며, 총 조회수와 수집 시작·최종 관측·집계 갱신 시각을 표시합니다. 마우스 사용 시 그래프 호버 위치의 툴팁으로 값과 관측 시각을 확인하며, 터치와 표의 날짜 버튼은 선택 정보 영역에 표시합니다. 대표 영상 불일치 시 통계 대신 곡 정보 재조회를 안내합니다.
- 일별 증가량은 연속된 한국 날짜의 관측값 차이입니다. 미수집은 `미수집`, 전날 값이 없으면 `계산 불가`, 실제 0은 `0회`로 구분하며 결측을 건너뛰어 계산하거나 음수 차이를 0으로 바꾸지 않습니다. 현재 API는 조회 범위 직전 날짜를 제공하지 않으므로 범위 첫날은 계산 불가입니다. 오늘은 부분 집계 표시와 옅은 점선 막대를 사용합니다.
- 막대축은 0을 포함하고 실제 데이터 범위로 상한을 정합니다. 곡·기간 간 공통 축 범위는 아직 확정하지 않았으며 Figma 예시 수치를 고정하지 않습니다.
- 같은 원곡의 다른 커버는 서버의 `relatedSongs`를 순서대로 표시합니다. 같은 원곡·다른 확정 멤버 조건과 정렬은 서버에서 적용하며 최대 6개이고 추가 페이지는 없습니다. 반환된 커버가 없으면 섹션 전체를 숨깁니다.
- 상세 조회 실패와 통계 조회 실패는 독립적으로 처리합니다. 즐겨찾기 저장·해제와 플레이리스트 선택·곡 추가를 제공합니다.

## 멤버 목록과 상세

- `/members`: 홈과 목록 캐시를 공유하며 졸업 멤버를 포함한 서버 순서를 유지합니다. 커서 추가 조회, 중복 제거, 로딩·빈 목록·실패 재시도를 제공합니다.
- `/members/:memberId`: 프로필 이미지·유닛·기수·활동 상태와 등록된 YouTube·치지직·X 링크를 표시합니다. 미등록 유닛·기수·공식 링크는 추정하지 않고 생략하며, 이미지 미등록·실패에는 대체 표시를 사용합니다. 졸업 멤버의 상세와 공개 곡도 조회할 수 있습니다.
- 전체·오리지널·커버 곡 수는 API 집계를 그대로 사용합니다. 공동 참여곡은 전체에 포함되며 별도로 더하지 않습니다.
- 참여곡은 전용 멤버 API로 조회합니다. 전체·오리지널·커버, 공동 참여곡만, 최신순·조회수순을 조합하며 조건은 URL에 보관합니다. 새 조건은 기존 커서를 사용하지 않고 첫 페이지부터 조회합니다.
- 스크롤 또는 더 보기로 추가 조회합니다. 일반 추가 조회 실패는 기존 목록과 커서를 유지하며, `409 VIEW_PUBLICATION_CHANGED`는 현재 필터의 캐시를 초기화하고 첫 페이지부터 조회합니다.
- 멤버 상세와 곡 목록의 로딩·오류를 독립적으로 처리합니다. 공개 곡이 없어도 프로필은 유지하며, 잘못된 UUID는 요청하지 않습니다. 없는 멤버·공개 불가 응답은 기존 상세 대신 접근 불가 안내를 제공합니다.
- 디자인 기준: [PC 멤버 목록](https://www.figma.com/design/XNF3BzVHQNt38qhNl0psyB?node-id=4-267), [PC 멤버 상세](https://www.figma.com/design/XNF3BzVHQNt38qhNl0psyB?node-id=38-7065), [모바일 멤버 상세](https://www.figma.com/design/XNF3BzVHQNt38qhNl0psyB?node-id=38-10387).

## 다인 참여와 특별 목적 표시

- 참여 인원 제한은 `multipleParticipants`를 사용합니다. `true`이면 확정 참여자 2명 이상이며, `false` 또는 생략하면 인원 제한이 없습니다. 곡 목록과 멤버별 곡 목록은 신규 파라미터만 전송합니다.
- 멤버의 공동 참여곡 수는 `songCounts.multipleParticipants`를 사용합니다. deprecated 호환 집계는 표시 기준으로 사용하지 않습니다.
- 곡 카드·상세는 참여 인원으로 콜라보 배지를 만들지 않습니다. 특별 목적 배지는 `isSpecialEvent`가 참일 때 `specialEventLabel` 문구를 표시하며, 문구가 없으면 기존 대체 문구인 “특별한 날”을 사용합니다.
- 기존 멤버 주소의 `collaboration` 조건은 새 필터로 읽고 다음 UI 변경부터 새 이름으로 URL을 작성합니다. 신·구 조건이 충돌하면 곡 요청을 막고 필터 초기화를 안내합니다.

## Google 로그인

- `/login`: PC·모바일 / 라이트·다크 Google 로그인 카드, 확인 중 스켈레톤, 실패·취소 인라인 안내를 제공합니다. Google 아이콘은 Figma의 `140:10871` 자산을 사용합니다.
- 브라우저를 `/api/v1/auth/google?returnTo=...`로 이동시켜 인증을 시작합니다. Vite 개발 실행에서만 `loginClient=local`을 추가하고 프로덕션 빌드에서는 생략합니다. fetch로 OAuth를 실행하거나 Google 토큰을 보관하지 않습니다. `/login?returnTo=원래경로&loginResult=...`로 복귀하면 안내 파라미터를 주소에서 제거하고 `/me`로 세션을 확인합니다.
- `loginResult=success`만으로 인증을 판단하지 않습니다. 취소·실패 시 기존 세션은 유지하고 현재 계정으로 계속하기를 제공합니다. 세션 조회 장애는 비로그인과 구분해 재시도를 안내합니다.
- `returnTo`는 내부 UI 경로만 허용하며 검색 조건·중복 파라미터·해시를 유지합니다. 외부 URL·API·actuator·로그인 루프·경로 우회·서버 길이 제한 초과는 보관함으로 대체합니다.
- `/library`는 세션 확인 후 진입합니다. 비로그인은 현재 경로를 보관해 로그인으로 안내합니다. 즐겨찾기 목록은 `/library`, 플레이리스트 목록은 `/library/playlists`에서 제공합니다.
- 로그아웃은 POST와 CSRF 헤더를 사용합니다. 성공 시 개인 캐시·진행 중 요청과 세션 캐시를 정리하며 실패를 자동 재전송하지 않습니다. 응답이 유실될 수 있으므로 실패 후 `/me`로 재확인합니다. 사용자가 재시도하면 새 CSRF를 조회합니다.
- 브라우저가 다시 활성화되면 세션을 재확인하고 만료 시 보호 화면을 숨깁니다. 로그인 동작은 고정 API 응답을 사용하는 PC·모바일 브라우저 테스트로 검증합니다.

### 통합 환경의 OAuth 복귀 설정

백엔드 `41309f9`의 로컬 Google 로그인 콜백 계약을 사용합니다.

```ini
VITE_API_BASE_URL=/api/v1
API_PROXY_TARGET=https://stelody-backend.onrender.com
```

- 개발 주소는 **`http://localhost:5173`**을 사용합니다. `127.0.0.1`이나 프로덕션 미리보기의 4175 포트 대신 `npm run dev`로 실행한 주소에서 인증합니다.
- `/api` 전체를 `changeOrigin: true`로 프록시하므로 Google 인증 시작·authorize·callback, `/me`, CSRF, 로그아웃이 같은 브라우저 origin을 사용합니다. `Set-Cookie`의 `Secure`·`HttpOnly`·`SameSite`·`Path`·만료 속성을 변경하지 않습니다.
- `loginClient=local`은 서버에 등록된 로컬 콜백을 선택합니다. Google 인증 후에는 서버가 검증한 내부 `returnTo` 경로로 `http://localhost:5173`에 복귀합니다. 운영 요청은 `loginClient`를 생략하고 기존 운영 콜백을 사용합니다.
- 로컬 콜백 선택은 일반 Google 로그인에만 적용됩니다. YouTube 연결·탈퇴 재인증은 각각 별도 연동 범위입니다.
- 별도 프론트 도메인 배포의 API 프록시·복귀 주소·쿠키 설정은 배포 시 검증합니다.
- 운영 백엔드와 연결한 Chromium에서 Google 이동 주소의 로컬 콜백, `Secure`·`HttpOnly`·`SameSite=Lax` 세션 쿠키 저장, 취소 후 로컬 로그인 화면 복귀, CSRF 조회 200·로그아웃 204·이후 `/me` 401을 확인했습니다. 실제 Google 계정 로그인 후 로컬 복귀와 새로고침 후 로그인 유지는 사용자가 브라우저에서 직접 확인했습니다.

## 즐겨찾기

- 곡 상세에서 저장·해제하고, 보관함 카드에서 해제합니다. 홈·전체곡·검색·멤버 참여곡의 일반 카드에는 즐겨찾기 버튼을 표시하지 않습니다. 곡별 상태는 계정·곡 ID로 공유하고, 처리 중에는 같은 곡의 모든 버튼을 잠급니다. 상태 확인 실패 시 다시 확인은 조회만 수행합니다.
- 비로그인 클릭은 현재 탭의 `sessionStorage`에 곡 ID·저장 의도·복귀 경로를 5분간 보관합니다. 세션 확인이 끝난 로그인 복귀 화면에서 준비한 작업만 원래 경로에서 한 번 실행하며, 실행 전에 삭제해 새로고침·중복 마운트로 반복하지 않습니다. 취소·실패 시 실행하지 않고, 만료된 계정의 작업은 다른 계정 로그인에서 폐기합니다. 저장소 차단 시 로그인 후 직접 버튼을 다시 누르도록 안내합니다.
- `/library`는 최근 저장순으로 20개씩 조회합니다. 서버의 전체·이용 가능 곡 수를 표시하며 페이지 사이 중복 곡 ID를 제거합니다. 이용 불가 항목은 곡 링크 없이 안내와 해제 버튼을 표시합니다.
- 저장·해제 후 곡 상태와 보관함 첫 페이지를 갱신합니다. 추가 페이지 오류는 기존 목록을 유지하며 잘못된 커서는 첫 페이지부터 다시 조회합니다. 401은 세션과 개인 캐시를 정리하고, 403·404는 받은 목록 대신 접근 불가 화면을 표시합니다.
- 변경 요청에는 기존 쿠키·CSRF 처리를 사용하고 자동 재전송하지 않습니다. 네트워크·서버 오류로 결과가 불확실하면 상태 조회로 원하는 결과가 반영됐는지만 확인합니다. 확인 실패와 한도 초과는 사용자에게 안내합니다.
- 디자인 기준: [PC 즐겨찾기](https://www.figma.com/design/XNF3BzVHQNt38qhNl0psyB?node-id=4-926), [모바일 즐겨찾기](https://www.figma.com/design/XNF3BzVHQNt38qhNl0psyB?node-id=38-10915), [즐겨찾기 버튼](https://www.figma.com/design/XNF3BzVHQNt38qhNl0psyB?node-id=70-10267). PC·모바일 / 라이트·다크의 정상·로딩·빈 목록·오류·접근 불가 화면을 확인했습니다.
- 실제 로그인 환경의 저장·보관함 반영·새로고침 후 유지·해제는 사용자가 브라우저에서 확인했습니다. 로그인 취소·재개·중복 전송 방지·오류·추가 페이지는 고정 API 응답으로 자동 검증합니다.

## 플레이리스트

- `/library/playlists`: 본인 목록의 이름·전체 곡 수·이용 가능 곡 수를 서버 순서대로 표시합니다. 빈 목록은 첫 목록 만들기로 연결하고, 목록 열기는 상세 조회, 비어 있는 목록의 곡 찾기는 검색으로 연결합니다. 커서 추가 조회·빈 상태·로딩·오류·접근 불가·재시도를 제공합니다.
- `/library/playlists/new`: 이름의 앞뒤 공백을 제거하고 1~50자로 검증해 생성합니다. 성공하면 새 목록 상세로 이동합니다. 필드별 서버 오류와 한도를 안내하고 실패 시 입력을 유지합니다. 생성 결과가 불확실하면 재전송을 막고 목록 확인을 제공합니다.
- 곡 상세의 `＋ 플레이리스트`는 추가 선택창을 엽니다. `songId`를 포함한 목록 조회의 `containsSong`으로 이미 담긴 곡을 구분하고, 선택한 목록의 `version`과 곡 ID로 추가합니다. 성공하면 목록을 갱신하고 선택창을 닫습니다. 일반 곡 카드에는 추가 버튼을 배치하지 않습니다.
- 선택창에서 새 목록을 만들고 곡을 담을 수 있습니다. 생성 성공 후 곡 추가만 실패하면 생성된 목록을 유지하며 재시도에서 다시 생성하지 않습니다. 버전 충돌은 최신 목록을 보여준 뒤 사용자가 다시 담도록 합니다. 변경 요청은 자동 재전송하지 않습니다.
- 비로그인 시 Google 로그인 후 원래 곡 상세에서 선택창을 다시 엽니다. 로그인 복귀만으로 목록을 생성하거나 곡을 추가하지 않습니다. 저장 의도는 즐겨찾기와 구분하며 탭 단위 만료·계정 일치·안전한 복귀 경로 규칙을 공유합니다.
- `/library/playlists/:playlistId`: 저장된 순서대로 썸네일·제목·참여자를 표시하고 커버곡에는 원곡 정보를 표시합니다. 상단은 총 곡 수와 이용 불가 곡 수를 구분하며, 이용 불가 곡이 없으면 해당 문구를 숨깁니다. 이용 불가 항목은 순서를 유지하며 곡 정보·링크를 숨깁니다. 페이지 간 버전이 다르면 합치지 않고, 잘못된 커서·버전 충돌은 첫 페이지부터 다시 조회합니다. 이름 변경·목록 삭제·곡 제거·순서 편집은 후속 기능입니다.
- 개인 Query 키는 계정과 목록·곡 ID로 구분합니다. 세션 만료는 개인 캐시를 정리하고 로그인으로 연결하며, 403·404는 기존 개인 목록 대신 접근 불가를 표시합니다. 선택창은 포커스 이동·Escape·원래 버튼으로 포커스 복귀를 지원하며 저장 중에는 닫기·중복 제출을 막습니다.

## API 계약

`openapi/stelody.json`은 로컬 Google 로그인 콜백 지원 기준 커밋 `41309f9`([PR #61](https://github.com/MinHyukJi1226/Stelody/pull/61)) 이후의 운영 OpenAPI 스냅샷입니다. 운영 명세에서 `loginClient=local` 반영을 확인하고 교체했습니다. 저장 시 프로젝트 JSON 포맷과 기존 키 순서를 적용하므로 파일 바이트 일치를 의미하지 않습니다.

명세는 수동으로 편집하지 않습니다. 백엔드 변경 시 해당 커밋의 검증된 CI 아티팩트에서 교체하고 아래 명령으로 타입을 생성합니다.

```sh
npm run api:generate
npm run api:check
```

생성 타입은 `src/shared/api/generated/schema.d.ts`에 보관합니다. `api:check`는 외부 서버를 호출하지 않고 저장된 명세에서 다시 생성한 결과를 비교합니다. 새 타입이 현재 운영 서버와 일치하는지는 연동 시 별도 확인합니다.

공통 클라이언트는 `/`로 시작하는 API 상대 경로를 받습니다. 공개 GET은 CSRF를 조회하지 않고, 변경 요청은 메모리에 보관한 CSRF 토큰을 사용합니다. 동시 변경의 토큰 조회는 공유합니다. `401`·`403` 및 로그아웃 후 토큰을 비웁니다. 로그인·재인증 완료 후 기능 모듈에서 `apiClient.invalidateCsrf()`를 호출해야 합니다. 다음 변경 요청에서 새 토큰을 조회합니다.

변경 요청은 자동 재시도하지 않습니다. `ApiError`의 `status`, `code`, `fieldErrors`, `traceId`로 분기하고, 알 수 없는 오류는 일반 안내로 처리합니다. 검색 요청 취소에는 `signal`을 전달합니다. 요청의 제네릭 타입은 TypeScript 계약이며 응답 전체의 런타임 검증을 의미하지 않습니다.

개인 데이터를 localStorage에 저장하지 않습니다. 개인 기능의 Query 키는 `['private', userId, ...]`를 사용하며 계정 전환·세션 만료·로그아웃 시 해당 캐시와 진행 중 요청을 제거합니다. 공개 곡·멤버 캐시는 유지합니다.

## 검증

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

`check`는 API 생성 타입, lint, 포맷, 단위·모듈 테스트, 타입 및 프로덕션 빌드를 검사합니다. E2E는 빌드된 앱을 4173 포트로 실행합니다. 고정된 API 응답으로 홈 조회·추천 갱신·빈 결과·실패 재시도·커서 추가 로딩·중복 제거·뒤로 가기 위치 복원과 데스크톱·모바일 공통 조작을 확인합니다. 운영 데이터나 계정에 의존하지 않습니다.

CI는 기존 Backend CI에서 재사용 Frontend CI를 호출합니다. 최종 `required-checks`와 main 이미지 게시가 프론트 검증 성공도 요구합니다. 배포 방식과 프론트 배포 산출물 연결은 아직 변경하지 않았습니다.

실제 Google 계정 인증 성공·세션 유지는 `http://localhost:5173` 개발 환경에서 확인합니다. YouTube·관리자 계정 연동은 해당 기능에서 검증합니다.
