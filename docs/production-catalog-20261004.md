## 이관 방법

로컬 DB의 일관된 읽기 전용 스냅샷에서 공개 카탈로그·원곡·아티스트·별칭·참여 관계·채널·검수 후보·탐색 위치만 추출했다. 회원·즐겨찾기·개인 목록·세션·OAuth 토큰·이전 수집 실행·과거 조회수는 제외했다. 운영에서 새로 로그인한 사용자 계정을 유지했다.

운영 카탈로그가 비어 있고 자동 공개가 꺼져 있는지 확인한 뒤 수집기와 같은 advisory lock과 대상 테이블 잠금을 사용했다. 스테이징 자료의 개수·대표 영상 소속·공개 조건을 검사하고, FK를 끄지 않은 상태로 같은 트랜잭션에서 자료와 곡별 IMPORT 감사 기록 360개를 저장했다. 감사에는 실제 DB 실행 역할과 `actor_id=null`을 기록했다.

곡·멤버·영상 ID는 유지했다. 후보 ID는 운영 네임스페이스로 다시 만들었으며 로컬 `reviewId`를 재사용하지 않았다. 영상의 조회수 수집 시작 시각은 비워 두어 실제 운영 관측부터 시작하도록 했다. 먼저 ROLLBACK 검증을 통과한 동일 스냅샷을 실제 반영했다.

이관 스냅샷 SHA-256: `7ffde5cc922aa262f38f156a6f2417376464e415120884b980f6ca00c0c764fe`. 실행 SQL·전체 추출 자료·비공개 설정은 Git에 포함하지 않았다. 이 절차는 신규 빈 카탈로그에 대한 일회성 이관이며 기존 운영 자료에 재실행하지 않는다.

## 실제 API 검증

운영 HTTPS에서 전체 목록 페이지를 순회해 360개 고유 곡을 확인했다. 360곡 상세의 제목·유형·대표 YouTube ID·영상 종류·멤버·외부 참여자를 명세와 대조했다. 11명 각각의 상세·표시 곡 수·실제 목록 수, 활동/졸업·곡 유형·공동 참여 필터, 별칭 검색과 중복 없는 추천 20개도 통과했다.

수집 후 공개 목록에서 실제 조회수·관측 시각을 확인했다. 한 곡의 `/views?days=7`은 오늘만 관측값을 반환하고 이전 6일은 null을 유지했다. 과거 조회수를 추정하거나 로컬 표본으로 채우지 않았다.

## 원격 저장 지연 수정

첫 수집은 첫 50개 영상의 저장 중 `DATABASE_ERROR`로 실패했다. 실제 Supabase에 동일 배치를 저장하고 전체 롤백하는 진단에서 `TransactionTimedOutException`이 약 10.23초에 발생했다. 영상마다 최대 5개 SQL을 따로 보내는 왕복이 누적된 것이 원인이었다.

기존 10초 트랜잭션 제한을 유지하며 SQL별 JDBC 배치로 묶었다. 소유 토큰·영상별 갱신 조건·시간별 중복 방지·일별 최신 관측 조건·전체 롤백은 유지했다. 같은 원격 진단은 약 0.83초에 성공하고 롤백됐다. 수정한 로컬 실행 파일로 실패 작업을 두 번째 시도에서 재개하여 360개 수집과 공개 조회수 게시를 완료했고 신규 탐색도 성공했다. 이 시점의 Render 웹 릴리스는 변경하지 않았다.

200ms의 문장 실행 지연을 넣은 50개 배치 저장과, 마지막 일별 관측 오류 시 50개 전체 롤백·이전 공개 게시본 보존을 통합 테스트로 확인했다. `check bootJar`에서 단위 185개·통합 381개, 총 566개가 실패·오류·건너뜀 없이 통과했고 포맷 검사도 성공했다. workflow는 actionlint와 인증서 정상·손상·비인증서·미입력 조건 검사를 통과했다.

## 정기 실행 준비 상태

GitHub runner에 Supabase 공개 CA를 준비·검사·삭제하는 workflow 변경과 수집 전용 설정을 준비했다. Secrets에는 DB URL·수집 계정·수집 비밀번호·YouTube API 키·공개 CA 5개만 필요하다. 웹·관리자·마이그레이션·OAuth 자격 증명은 전달하지 않는다.

이 기록 시점에는 변경 코드의 커밋·푸시·PR과 GitHub Secrets/Variables 등록을 완료하지 않았다. 일회성 수집 성공은 예약 수집 활성화를 뜻하지 않는다. 변경을 main에 반영하고 CI를 통과한 뒤 [정기 수집 절차](deployment-operations.md#4-정기-수집-활성화)에 따라 수동 실행·다음 예약 실행 기록을 확인해야 한다.

자동 공개·수동 재시도·급상승 정책 플래그와 관리자 권한은 이 작업에서 활성화하지 않았다. 등록된 곡의 조회수 갱신, 신규 후보 탐색과 신규 곡의 검수·공개는 각각 다른 단계다.
