2026-09-29 사용자 합의. 개발 기준서를 우선하며 애매한 제품 정책은 구현 전에 확인한다.

- 공식 MV·동일 녹음 음원 영상·재업로드는 하나의 곡에 연결한다. 공식 MV가 대표 영상이며 조회수 기준이다. MV 부재·이용 불가 시 대체 규칙은 미결정이다.
- 2026-09-30 보완: 오리지널곡에 공식 MV가 없으면 공식 음원 영상을 대표로 사용한다. 커버는 해당 공식 커버 영상을 사용한다. 기존 대표 영상이 이용 불가해진 경우 자동 대체 규칙은 아직 정하지 않았다.
- 외부 참여자도 표시하며 공동 참여 판정에 포함한다.
- 멤버 복수 필터는 OR 조건이다.
- 일별 조회수는 KST 해당 날짜의 마지막 성공 관측값이다.
- Google 단일 가입·로그인으로 변경한다. Google 인증 성공 시 회원가입을 완료하며 자체 이메일 인증·비밀번호 변경·재설정은 제외한다.
- Google 로그인과 YouTube 내보내기 권한은 분리한다. 내보내기 시 추가 동의를 요청하며 거절해도 개인 목록 사용은 유지한다.
- YouTube 플레이리스트 내보내기는 MVP 포함을 목표로 한다. OAuth 연결·동의와 외부 조건은 해당 기능 작업 시 확인한다.
- 관리자 수동 재시도 버튼은 백그라운드 수집을 요청하고 진행·결과를 표시한다. 구체적인 작업 전달 방식은 수집 기능 구현 시 설계한다.
- 초기 채널·곡 자료와 외부 설정은 필요한 시점에 사용자에게 요청한다.

## 첫 작업 범위

실행 프로젝트, 프로필, Flyway 세션 스키마, 기본 접근 차단, PostgreSQL 통합 테스트 기반을 구성한다. 회원가입·로그인·업무 API는 다음 기능 단위로 구현한다. 아직 12시간 절대 세션 만료나 계정 상태 검증을 제공하는 인증 시스템은 아니다.

PostgreSQL 17은 운영 DB가 생성되기 전 로컬 검증용 선택이다. 운영 Supabase 메이저 버전 확인 후 Compose와 Testcontainers를 함께 맞춘다. 운영 DB 계정과 권한 분리는 실제 DB 준비 시 적용하며 로컬은 단일 개발 계정을 사용한다.

## 초기 검증 결과

- 보안 테스트 4개 통과. 설치된 Homebrew Java 21.0.12.1과 Docker Desktop 환경에서 `check bootJar` 통과(보안 테스트는 기존 성공 결과 재사용).
- PostgreSQL Testcontainers 통합 테스트 2개 통과. Flyway 마이그레이션, DB 세션 저장·조회·삭제, 30분 세션 유효기간, 공개 health 응답을 검증했다.
- 로컬 Compose의 PostgreSQL과 Mailpit 모두 healthy. 실제 실행 jar로 local 프로필 기동 후 마이그레이션 적용과 `/actuator/health`의 UP 응답, Mailpit 웹 화면 HTTP 200을 확인했다.
- GitHub Actions에는 `check bootJar`와 필수 검사 집계 job을 구성했다. 아직 푸시하지 않아 CI 실행 결과는 없다.
- 사용자의 Java 21 및 Docker 설치가 완료됐다. 검증용 백엔드는 확인 후 종료하고 로컬 PostgreSQL·Mailpit은 실행 상태로 유지한다.


## Google 로그인 구현 범위

기존 이메일 인증 결정은 위 Google 로그인 결정으로 대체한다. `sub`를 Google 계정 고유 키로 사용하고 내부 회원 ID는 UUID로 유지한다. API 서버가 Google 인증 코드를 교환하고 Spring Security 인증 후 JDBC 세션을 생성한다. Google 토큰의 장기 보관은 이번 로그인 범위에 없다.

이번 단계는 가입·로그인·내 정보·로그아웃·CSRF 및 세션 만료 검증이다. 탈퇴 재인증, 운영 관리자 지정, 로그인 후 원래 화면 복귀·저장 의도 복원, YouTube 추가 권한·토큰 보관은 후속 기능에서 구현한다. 실제 Google OAuth 클라이언트 발급은 사용자가 진행하며, 발급 전에는 모의 제공자로 테스트한다.

## 공개 조회 구현 범위

2026-09-30. 작품·개별 곡·업로드를 분리하고 멤버/외부 참여자와 별칭을 연결한다. 로그인 없는 곡·멤버 조회, 검색·필터·관련도/최신/조회수 정렬, 커서 페이지와 멤버별 공개 곡 수를 구현한다. 실제 콘텐츠 없이 PostgreSQL 테스트 자료로 검증하며 관리자 입력·수집·통계 차트는 후속 범위다. 계약과 제한은 [공개 API 문서](public-catalog-api.md)에 기록한다.

## 즐겨찾기 구현 범위

2026-09-30. 로그인한 회원의 저장·해제·저장 여부와 내 목록 조회를 구현한다. PUT·DELETE는 멱등하고 소유자는 세션에서 결정한다. 기본 5,000곡 한도와 동시 요청을 회원별 잠금으로 처리한다. 이용 불가 곡도 저장 관계를 유지하며 제목·썸네일·재생 링크가 없는 자리표시자로 표시한다. 계약은 [즐겨찾기 API 문서](favorites-api.md)에 기록한다. 개인 플레이리스트·YouTube 내보내기·프론트 화면은 후속 기능이다.

## 개인 플레이리스트 구현 범위

2026-10-01. 목록 생성·조회·이름 수정·삭제, 곡 추가·제거·조회, 전체 항목 순서 변경을 구현한다. 기본 50개 목록·500곡 한도와 계정별 접근을 검증한다. 변경 요청은 현재 `version`을 받아 JPA `@Version`으로 충돌을 검사하고 부모 버전을 갱신한다. 이용 불가 곡도 위치를 유지하며 자리표시자로 표시한다. 전체 항목 ID를 검증한 뒤 한 트랜잭션에서 순서를 교체한다. 이름 중복은 허용한다. 계약은 [플레이리스트 API 문서](playlists-api.md)에 기록한다. 프론트 화면과 YouTube 추가 동의·내보내기는 후속 작업이다.
