시험은 기존 회원 자료를 변경하지 않고 전용 임시 계정 두 개를 사용했다. 첫 계정은 API 탈퇴로 제거했고 두 번째 계정은 검증 후 직접 정리했다. 복원 DB 두 개·시험 역할·덤프·시험 개인키·세션 파일도 정리했다. 운영 DB에 복원하거나 실제 회원을 탈퇴시키지 않았다.

## 발견하여 수정한 문제

YouTube 연결 해제 시 미완료 작업만 취소하고 완료 작업의 외부 목록 ID·항목을 보관하던 동작을 수정했다. 연결 해제·권한 무효 확인 시 동의 요청과 모든 내보내기 기록을 제거한다. access 토큰은 즉시 지우고 철회 재시도에 필요한 암호화 refresh 토큰만 유지한다. 철회 성공 시 잔여 자료를 삭제하며 이전 generation의 철회 결과가 새 연결 자료를 지우지 않도록 한다.

회귀 검증은 완료 작업 삭제, 다른 계정 보존, 늦은 작업자 응답의 자료 재생성 방지, 오래된 철회 결과의 새 연결 보존, 철회 실패 시 회원 유지까지 포함한다. 수정 코드는 이번 변경에 포함하며 운영 반영은 별도 배포 이후에 확인한다.

## 외부 백업 준비

카드 등록 없는 Backblaze B2용 업로드·다운로드·암호화·버전별 만료 정리를 준비했고 10월 7일 GitHub 작업을 활성화했다. [계정·저장소와 활성화·검증 기록](offsite-backup.md)을 따른다. 저장소 모의 응답 검증과 실제 클라우드 업로드를 구분한다.

회원 자료의 운영 복구는 완전한 탈퇴 기록을 확보해야 공개 재개할 수 있다. 시험용 UUID 기록은 전체 운영 탈퇴 기록의 완전성을 증명하지 않는다. 현재 복구 스크립트는 이 확인이 없으면 복구를 거부하고, 성공해도 `readyForPublicTraffic=false`로 남긴다.

## B2 실제 연결 검증

버킷 `stelody-backups`와 `stelody/backups/` 경로에 제한된 키를 확인했다. 공개 ACL이 없고, 접두어의 숨김 1일·이전 버전 삭제 1일 규칙이 활성화된 것을 API로 읽었다. 개인정보 없는 시험 파일을 암호화해 업로드하고, 다운로드·복호화 원본 일치와 익명 접근 401을 확인했다. 같은 키의 만료된 이전 버전을 VersionId로 영구 삭제하고 미만료 버전이 남는 것도 확인했다. 시험 파일의 모든 버전은 정리했다.

이 10월 5일 시험은 실제 일일 수명 주기 작업과 GitHub 예약 백업 실행을 확인한 결과는 아니다. 당시 복구용 운영 키와 GitHub 등록용 값은 무시되는 비공개 로컬 파일에만 준비했으며 개인키는 GitHub 등록용 값에서 제외했다.

10월 5일 운영 DB에서 새로 만든 백업(817599 bytes)을 운영 복구 공개키로 암호화해 B2에 임시 업로드했다. 내려받아 복호화한 PostgreSQL 덤프가 원본 바이트 및 checksum과 일치했고 `pg_restore --list`로 archive를 검증했다. 운영 DB 복원은 하지 않았다. 검증 후 원격 파일의 모든 버전과 로컬 평문·시험 접속 자료를 제거했다. 이때 자동 예약 백업은 비활성이었다.

## GitHub 자동 백업 활성화 — 2026-10-07

사용자 승인 후 `production-backup` environment의 Secrets 6개·변수 3개를 등록하고 `main` 브랜치만 사용할 수 있게 제한했다. 저장소 변수 `BACKUP_ENABLED=true`를 적용했다. 운영 복구 개인키는 GitHub에 등록하지 않았다.

[첫 수동 실행 #11](https://github.com/MinHyukJi1226/Stelody/actions/runs/37609917358)은 KST 19:49에 시작해 1분 16초 후 성공했다. 운영 DB 백업, age 암호화, 비공개 B2 업로드, VersionId를 지정한 암호문 무결성 확인, 실행기의 임시 자료 정리를 확인했다.

그 B2 파일을 실제로 내려받아 복호화한 뒤 외부 네트워크와 공개 포트가 없는 별도 PostgreSQL 17 컨테이너에서 `pg_restore`와 정리 SQL로 검증했다. 공개 360곡·11멤버·V19, 제외 대상 14개 테이블의 행 0개, 자동 공개 비활성 및 조회수 공개 포인터 초기화를 확인했다. ACL도 복원했다. 시험 DB와 로컬 평문·다운로드 파일은 제거했고 실제 B2 백업은 보관했다.

완전한 운영 탈퇴 기록을 만들거나 서비스를 중단했다고 가정하지 않았다. `complete=false` 기록의 거부를 확인했으며 이 오프라인 archive 시험은 `database.py restore`를 이용한 전체 운영 복구·트래픽 재개 완료를 뜻하지 않는다. 첫 예약 실행, B2 일일 수명 주기 삭제 관찰과 독립 탈퇴 기록 확보는 남아 있다.

운영자는 복구 개인키의 Mac 외부 사본을 보관했다고 확인했다. 보관 위치와 사본 내용은 수집하지 않았으며 외부 사본 자체의 복호화 시험은 수행하지 않았다.
